ABSTRACT

Placement Tracker is a web-based application developed to centralize and automate the tracking of job applications, Data Structures & Algorithms (DSA) preparation progress, and competitive coding profiles. Built using **Node.js, Express.js, MongoDB/Mongoose**, and a highly responsive **HTML5/CSS3/Vanilla JavaScript** frontend, the system streamlines the career placement pipeline for engineering students.

The system provides students with a simple and interactive dashboard divided into three core functional segments. An **Application Tracking Dashboard** enables logging, modifying, and filtering student job applications (Applied, Online Assessment, Interview, Selected, Rejected). A **DSA Preparation Tracker** keeps a record of questions solved across major topics (e.g., Array, Matrix, String) categorized by difficulty (Easy, Medium, Hard). A **Coding Profile Aggregator** crawls student statistics in real-time from competitive programming domains including **LeetCode** (GraphQL API), **Codeforces** (REST UserInfo API), **GitHub** (REST API), and **GeeksforGeeks** (custom HTML parser) with built-in caching to optimize page load speeds.

The platform also incorporates JWT-based Authentication for session security, Nodemailer for verification OTP dispatches, and responsive CSS grids supporting mobile views. Streamlining profile updates and password reset via OTP email authentication represents a major security enhancement.

Keywords: Node.js, Express.js, MongoDB, Mongoose, Competitive Coding, Web Crawler, Job Tracker, Password Recovery.

Implementation Software and Hardware:

  • Express.js (v5)
  • MongoDB Atlas / Mongoose
  • HTML5, CSS3, ES6 JavaScript
  • Axios HTTP Client
  • Cheerio / Scraper
  • Nodemailer & JWT

Chapter 2: Technology Specification

2.1 Language Learned

The entire Placement Tracker project is implemented in JavaScript (modern ECMAScript), HTML5, and CSS3. Using a single programming language (JavaScript) across both the client-side files and the Express.js server-side backend considerably reduces context-switching and allows shared object formats.

2.1.1 Core JavaScript Concepts

  • Variables and scoping using let and const.
  • Arrow functions and the lexical binding of this.
  • Promises and the async/await syntax for asynchronous network operations and database queries.
  • Array higher-order functions such as map, filter, reduce, and forEach used extensively for transforming API response data before rendering.
  • DOM Manipulation methods like querySelector, addEventListener, and dynamic innerHTML injection to create responsive states.

2.2 Tools and Environment

2.2.1 Frontend Stack

  • HTML5 & CSS3: Used to define standard document structure and styling. The UI utilizes CSS custom properties (variables), gradients, transitions, and flexbox/grid alignments.
  • Local Storage: Used to persist authentication tokens (JWT) and user data to avoid database hits on page refreshes.
  • Vanilla JS DOM hooks: Dynamic routing and updates handled on client side using JS modules (`config.js`, `profile.js`).

2.2.2 Backend Stack

  • Node.js: Serves as the runtime foundation.
  • Express.js (v5): Used to implement REST routes, handle CORS requests, parse JSON bodies, and orchestrate middleware.
  • MongoDB Atlas: A document-oriented NoSQL database used to persist collections.
  • Mongoose: An Object Data Modelling (ODM) library used to structure schemas and interact with MongoDB.
  • Nodemailer: Used to dispatch security OTP emails for authentication recovery.
  • Axios & Cheerio: Employed to construct requests and extract statistical values from coding websites.

Chapter 3: Project Description

3.1 Overview

Placement Tracker is a MERN/Vanilla JS web application designed to digitize student placement tracking. In traditional college environments, students track their corporate applications on scattered spreadsheets and log DSA problems on notes. Placement Tracker solves this by providing a unified student portal. The frontend renders dashboards, tracks company interview status pipelines, logs sheet-wise DSA problems, and pulls coding analytics (ratings, problems solved, repositories) automatically.

3.2 System Architecture

1. Presentation Tier (Frontend Client)
Static HTML5 pages, CSS3 variables/grids/flexbox, Vanilla JS event listeners. Connects to backend using Axios.
2. Logic Tier (Express Server API)
Exposes REST endpoints, validates input, manages security middleware, scrapes third-party servers, dispatches OTPs.
3. Data Tier (Database Clusters)
MongoDB Atlas cloud instance. Collections: Users, Applications, DsaTopics, Drives, Otps. Mapped using Mongoose.

3.3 Data Models

3.3.1 User Model (User.js)

Field Name Data Type Default/Enum Description
name, email String Required Personal name and unique email keys.
password String Required Secure Bcrypt hashed password representation.
streakCount Number 0 Current consecutive daily usage streak.
badges Array (String) [] Gamification badges unlocked by the user.
codingProfiles Object {} Contains usernames: `{leetcode, gfg, codeforces, github}`.

3.3.2 Application Model (Application.js)

Field Name Data Type Validation / Enum Description
company, role String Required Corporate name and designation.
pkg String Required Salary package (LPA).
status String Applied, OA, Interview, Selected, Rejected State of the placement application.
user ObjectId Ref: 'User' Reference key to the applicant user.

3.3.3 DSA Topic Model (DsaTopic.js)

Stores tracking records of DSA topic sheets (e.g., Array, Matrix). Properties include name (String), easySolved, mediumSolved, hardSolved, and total counts for each category, mapping progress bars on the dashboard. Linked to User via Mongoose reference.

3.4 Authentication & Authorization

Auth uses JSON Web Tokens (JWT). When logging in, a token is signed with the user ID, stored on the client, and verified by server middlewares. To reset password from the profile, an OTP is dispatched to the user's email via Nodemailer. The user enters the OTP, which is validated against the MongoDB Otps collection before password updates are authorized.

3.5 Core Functional Modules

  • Applications Dashboard: CRUD utility for student job logs with pipeline visual status filters.
  • DSA Progress Tracker: Sheet-wise problem categories mapping progress.
  • Profile Analytics Aggregator: Calls APIs (LeetCode GraphQL, Codeforces User API, GitHub API) and scrapes GFG pages with user-agent headers. Caches outputs for 5 minutes in memory to prevent rate-limiting blocks.

3.6 REST API Endpoint Summary

Method Endpoint Authorization Description
POST /api/auth/register Public Registers a new student account.
POST /api/auth/login Public Validates user and issues JWT.
PUT /api/profile JWT (Header) Updates info and coding platform usernames.
GET /api/profile/coding-stats JWT (Header) Pulls and aggregates LeetCode, CF, GFG, GitHub stats.

Chapter 4: Limitations & Outcomes

4.1 Limitations of the Project

  • Scraper Vulnerability: GFG statistics scraping relies on the HTML page source. A change in the layout on GeeksforGeeks could break the regex extraction mechanism.
  • Third-party API dependency: If external APIs (LeetCode, GitHub, Codeforces) undergo downtime, the profile stats card will display placeholders until the APIs recover.
  • Client-side security: Storing JWT tokens in localStorage makes the application susceptible to cross-site scripting (XSS) risks compared to secure httpOnly cookie storage.

4.2 Learning Outcomes

This training resulted in transferable full-stack engineering outcomes:

  • Understanding RESTful API designs, HTTP statuses, and CORS constraints.
  • Proficiency in modeling relational-like documents in NoSQL databases using Mongoose.
  • Familiarity with secure authentication patterns (JWT authorization headers, Bcrypt password hashing).
  • Experience building a web scraper, handling XML/JSON responses, and implementing in-memory caching mechanisms.
  • Designing responsive glassmorphic interfaces using CSS grids, custom properties, and transitions.

4.3 Future Scope

The technology and application can be extended in multiple directions:

  • AI Integration: Integrating AI agents to review student resumes and map them against corporate job application requirements automatically.
  • Real-time Notifications: Introducing WebSocket connections for instant job drive notifications.
  • Tele-Mentorship: Adding tele-consultation or mock interview rooms utilizing WebRTC.
